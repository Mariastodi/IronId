Autenticação por Bearer token

Faça login e envie o token no cabeçalho Authorization das chamadas protegidas.

Primeiros passos

curl -X POST 'http://127.0.0.1:8000/api/login' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{"email":"admin@ironid.com","password":"password"}'

curl 'http://127.0.0.1:8000/api/members?per_page=8' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Accept: application/json'

Credenciais de exemplo exclusivas do ambiente local com seeder. No zsh, mantenha a URL com “?” entre aspas.

Reconhecimento

Envie {"descriptor": [128 números]}. Uma resposta bem-sucedida inclui data.member.name, matrícula, plano e data.check_in_id. O descritor não é retornado.

Leituras do mesmo aluno em até 60 segundos reutilizam o registro anterior. Planos vencidos ou inativos retornam 422.

Erros e filtros

401: autenticação · 403: permissão · 404: não encontrado · 422: validação · 429: limite de requisições.

Alunos: name, matricula, active, page, per_page (1–100). Histórico: member_id, date (AAAA-MM-DD), page, per_page.

Protótipo educacional. O reconhecimento não implementa prova de vida nem garante identidade para controle físico autônomo.
